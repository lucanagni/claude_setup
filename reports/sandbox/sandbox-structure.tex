\noindent\textbf{Goal.} Claude works freely in the current repo. Anything else in \texttt{\textasciitilde} needs your
approval. Secrets and the sockets that could escape the sandbox stay unreachable, whatever you approve.
Two threats are covered: Claude's mistakes and hostile code that Claude runs.

\noindent\textbf{Legend.}\\
\BLK\ no approval opens it (only a manual settings edit) \quad
\ASK\ you approve it each time \quad \FRE\ no prompt.

\section{Layers and how they connect}
Each tool call passes through the layers that apply to it. A call is allowed only if every layer allows it.

\begin{tabularx}{\linewidth}{@{}l l L@{}}
\toprule
\textbf{Layer} & \textbf{Applies to} & \textbf{What it does} \\
\midrule
1. Permission rules & all tools & \texttt{deny} > \texttt{ask} > \texttt{allow}. Secrets are denied for Read and Edit; toolchain
  reads are allowed; \texttt{ask} on \p{EnterWorktree}, \p{ssh}, \p{scp}, unsandboxed Bash. \\
2. PreToolUse hooks & Bash, Agent, Edit, Write & \p{git-guard.py}: branches and worktrees prompt.
  \p{outside-repo-guard.py}: edits outside the repo, in \p{.git/} or in Claude's config prompt.
  \p{bg-guard.py}: background jobs may not edit existing files. \\
3. Sandbox (bubblewrap) & Bash only & Own mount, PID and network namespaces. The filesystem is limited to the repo,
  toolchain dirs and \p{$TMPDIR}. Rules are re-read live from settings. \\
4. Network proxy & sandboxed Bash & Only \p{allowedDomains} pass freely; other hosts prompt (manual mode) or go to the
  auto-mode classifier. \\
5. SessionStart hook & each session & \p{sandbox-bootstrap.sh} adds the repo path to \p{allowRead} in the repo's
  \p{.claude/settings.local.json} and keeps that file out of git. \\
\bottomrule
\end{tabularx}

\medskip\noindent
\textbf{Key asymmetry.} The sandbox wraps \emph{Bash only}. The Read, Edit and Write tools are not sandboxed; for them,
layers 1 and 2 are the whole defence. That is why secrets have both a sandbox deny and a permission deny, and why
\p{outside-repo-guard.py} exists.

\section{Escalation when Bash is blocked}
Claude stops, names the path or host and why it needs it, then offers, in this order:
\begin{enumerate}
\item \textbf{Session:} you type \p{/add-dir}\ \p{<path>}. Opens reads and writes until the session ends.
\item \textbf{Permanent:} a prompted edit adding the path to \p{allowRead}/\p{allowWrite} in the repo's
  \p{.claude/settings.local.json}. Takes effect immediately.
\item \textbf{Unsandboxed retry:} only for git remote operations over ssh, or as a last resort you agree to. Always prompts.
\end{enumerate}
Claude never works around a block (copying files into the repo, other tools, other paths).

\section{Accepted risks}
\begin{itemize}
\item An approved unsandboxed retry has your full rights: secrets, sockets, and git hooks run unsandboxed.
  Read the command before approving.
\item In auto mode, the classifier, not you, may approve new network hosts.
\item Connectable system sockets (snapd, cups, avahi, acpid, journal, uuidd, userdb): no code execution without polkit,
  which is unreachable.
\item \p{~/.matlab/credentials} is readable: MATLAB's online licensing needs it.
\item Package caches (\p{conda-pkgs}, \p{claude-pip}) can be poisoned, but only envs that Claude creates use them.
\end{itemize}
